# ANI.DAT 格式分析 (修正版)

## 文件结构

```
偏移 0x00-0x05: 魔数 "LLLLLL"
偏移 0x06-0x07: 索引数量 (WORD) = 46 (但只有 9 个有效)
偏移 0x08-0x09: 保留
偏移 0x0A+:     索引表 (4 字节条目)
```

## 索引表

**格式**: 每个 4 字节条目是一个 AFM 数据的偏移值

**公式**: `offset = 4 * index + 6`

**有效索引**:

| 索引 | 偏移地址 | 帧数 | 说明 |
|------|----------|------|------|
| 0 | 0x0000002E | 96 | 第一个 AFM (启动动画?) |
| 1 | 0x000F4D5E | 51 | 已索引 |
| 2 | 0x0019018E | 26 | 未在旧分析中发现 |
| 3 | 0x001A7F4C | 28 | 已索引 |
| 4 | 0x001B0A3A | 12 | 未在旧分析中发现 |
| 5 | 0x001B974B | 35 | 已索引 |
| 6 | 0x0021DCEA | 12 | 未在旧分析中发现 |
| 7 | 0x0022870B | 17 | 已索引 |
| 8 | 0x0024A18E | 12 | 未在旧分析中发现 |

## 加载函数分析 (sub_20421)

```c
// 1. 打开文件
_rb_ = fopen("ANI.DAT", "rb");

// 2. 读取索引
fseek(_rb_, 4 * a5 + 6, 0);  // a5 = 索引号
fread(v8, 1, 8, _rb_);       // 读取 8 字节

// 3. 定位到 AFM 数据
fseek(_rb_, *(DWORD*)v8, 0); // 使用前 4 字节作为偏移

// 4. 读取 AFM 头
fread(v8, 1, 173, _rb_);     // 读取 173 字节头
frame_count = *(WORD*)(v8 + 165);  // 帧数在偏移 0xA5

// 5. 读取每帧
for (i = 0; i < frame_count; i++) {
    fread(frame_header, 1, 8, _rb_);  // 帧头
    fread(frame_data, 1, size, _rb_); // 帧数据
    sub_36FF4(param, frame_data);     // 解码帧
}
```

## 之前分析的错误

之前认为索引表是 8 字节条目 (start, end)，这是因为：
- 读取连续两个 4 字节条目时，恰好是两个相邻 AFM 的偏移
- 例如 index=0 时读取 8 字节: [0x2E, 0xF4D5E]，看起来像是 [start, end]
- 实际上是两个独立的索引条目

## 结论

所有 9 个 AFM 资源都在索引表中，索引表使用 4 字节条目格式。
