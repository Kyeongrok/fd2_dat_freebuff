# ANI.DAT 逆向分析报告

## 概述

成功逆向了 FD2 游戏的 ANI.DAT 文件格式，实现了 AFM (Animation File Manager) 动画的完整解码和渲染。

## 关键发现

### 1. 索引表结构 (修正)

- **索引公式**: `offset = 4 * index + 6`
- **条目大小**: 4 字节 (不是之前认为的 8 字节)
- **有效条目**: 9 个 AFM 资源

### 2. 帧头结构 (8 字节)

```
偏移 0-1: size (WORD) - 帧数据大小
偏移 2-3: param (WORD) - 解码参数
偏移 4-7: 保留/额外数据
```

### 3. 帧类型与命令流

帧数据是**命令流**，由 sub_36FF4 分发处理:

| 命令 | 函数 | 说明 |
|------|------|------|
| 0x00 | sub_36E3D | 填充调色板 (单色) |
| 0x01 | sub_36E57 | 复制调色板 (768 字节) |
| 0x02 | sub_36E65 | RLE 解码调色板 |
| 0x03 | sub_36EA7 | 多段复制 |
| 0x04 | sub_36EE0 | 填充缓冲区 |
| 0x05 | sub_36F08 | 复制数据到缓冲区 |
| 0x06 | sub_36F24 | RLE 解码像素 |
| 0x07+ | ... | 其他命令 |

### 4. RLE 解码规则 (命令 0x06)

基于 sub_36F24 反编译代码:

```
如果 (byte & 0xC0) == 0xC0:
  count = byte & 0x3F  # 低 6 位，范围 1-63
  color = 下一个字节
  写入 count 个 color
否则:
  直接写入该字节作为像素值
```

### 5. 调色板

- **格式**: DOS 6位调色板 (0-63)，需 ×4 转换为 8 位
- **大小**: 768 字节 (256 × 3)

## 技术细节

### 帧缓冲区

动画使用 64000 字节 (320×200) 的缓冲区存储当前画面。每帧通过命令更新缓冲区内容。

### 命令流处理

1. 读取命令字节
2. 根据命令类型执行相应操作
3. 更新缓冲区或调色板
4. 重复直到数据结束

### 帧间差异

大部分帧只包含与前一帧的差异，使用 RLE 压缩。这是典型的关键帧 + 差分帧动画格式。
