# ANI.DAT 역공학 분석 보고서

## 개요

FD2 게임의 ANI.DAT 파일 포맷을 성공적으로 역공학하여, AFM (Animation File Manager) 애니메이션의 완전한 디코딩 및 렌더링을 구현했습니다.

## 주요 발견

### 1. 인덱스 테이블 구조 (수정)

- **인덱스 공식**: `offset = 4 * index + 6`
- **항목 크기**: 4바이트 (기존에 8바이트로 추정했으나 수정)
- **유효 항목**: 9개의 AFM 리소스

### 2. 프레임 헤더 구조 (8바이트)

```
오프셋 0-1: size (WORD) - 프레임 데이터 크기
오프셋 2-3: param (WORD) - 디코딩 파라미터
오프셋 4-7: 예약/추가 데이터
```

### 3. 프레임 타입과 명령 스트림

프레임 데이터는 **명령 스트림**이며, sub_36FF4에서 디스패치 처리합니다:

| 명령 | 함수 | 설명 |
|------|------|------|
| 0x00 | sub_36E3D | 팔레트 채우기 (단색) |
| 0x01 | sub_36E57 | 팔레트 복사 (768바이트) |
| 0x02 | sub_36E65 | 팔레트 RLE 디코딩 |
| 0x03 | sub_36EA7 | 다중 구간 복사 |
| 0x04 | sub_36EE0 | 버퍼 채우기 |
| 0x05 | sub_36F08 | 버퍼로 데이터 복사 |
| 0x06 | sub_36F24 | 픽셀 RLE 디코딩 |
| 0x07+ | ... | 기타 명령 |

### 4. RLE 디코딩 규칙 (명령 0x06)

sub_36F24 디컴파일 코드 기반:

```
(byte & 0xC0) == 0xC0인 경우:
  count = byte & 0x3F  # 하위 6비트, 범위 1-63
  color = 다음 바이트
  color를 count개 출력
그렇지 않으면:
  해당 바이트를 픽셀 값으로 직접 출력
```

### 5. 팔레트

- **포맷**: DOS 6비트 팔레트 (0-63) → ×4 변환으로 8비트 변환 필요
- **크기**: 768바이트 (256 × 3)

## 분석 도구

### 작성된 도구

1. `afm_complete_decoder.py` — 전체 명령 스트림 디코더
2. `afm_rle_decoder.py` — RLE 디코더
3. `create_complete_gif.py` — GIF 애니메이션 생성기
4. `create_rle_gif.py` — RLE GIF 생성기

### 핵심 함수 (디컴파일 코드)

- `sub_20421`: ANI.DAT 메인 로더
- `sub_36FF4`: 프레임 디코딩 디스패처 (funcs_37012 함수 테이블 사용)
- `sub_36F24`: 픽셀 RLE 디코딩 (명령 0x06)
- `sub_111BA`: DAT 파일 공통 로더

## 기술 세부사항

### 프레임 버퍼

애니메이션은 현재 화면을 저장하기 위해 64000바이트 (320×200) 버퍼를 사용합니다. 각 프레임은 명령을 통해 버퍼 내용을 갱신합니다.

### 명령 스트림 처리

1. 명령 바이트 읽기
2. 명령 타입에 따라 해당 동작 실행
3. 버퍼 또는 팔레트 갱신
4. 데이터 끝까지 반복

### 프레임 간 차분

대부분의 프레임은 이전 프레임과의 차이만 포함하며, RLE 압축을 사용합니다. 이는 전형적인 키 프레임 + 차분 프레임 애니메이션 포맷입니다.
