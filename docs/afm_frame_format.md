# ANI.DAT AFM 프레임 포맷 분석

## 프레임 헤더 구조 (8바이트)

```
오프셋 0-1: size (WORD) - 프레임 데이터 크기
오프셋 2-3: param (WORD) - 디코딩 파라미터
오프셋 4-7: 예약
```

## 프레임 타입

| 타입 | 조건 | 설명 |
|------|------|------|
| 제어 프레임 | size = 0 | 초기화 명령 |
| 키 프레임 | size > 50000 | 전체 화면 데이터 (~64KB) |
| 차분 프레임 | 0 < size <= 50000 | 프레임 간 차이 데이터 |

## 프레임 시퀀스 분석 (첫 번째 AFM)

```
프레임 0: size=0, param=62714 (0xF4FA) - 초기화
프레임 1: size=0, param=256 (0x0100) - 팔레트 설정
프레임 2: size=15872, param=1 - 첫 번째 프레임 데이터
...
```

## 디코딩 흐름 (sub_20421)

```c
for (i = 0; i < frame_count; i++) {
    // 프레임 헤더 읽기
    fread(frame_header, 1, 8, file);
    size = frame_header[0];
    param = frame_header[1];
    
    // 프레임 데이터 읽기
    if (size > 0) {
        fread(frame_data, 1, size, file);
    }
    
    // 프레임 디코딩
    sub_36FF4(param, frame_data);
    
    // 지연
    delay(a6);
    
    // 종료 확인
    if (check_exit()) break;
    
    // 화면 갱신
    update_display();
}
```

## 프레임 디코딩 (sub_36FF4)

프레임 데이터는 **명령 스트림**이며, param이 루프 횟수를 제어합니다:

```c
for (; param; --param) {
    cmd = *data++;
    result = funcs_37012[4 * cmd](data);
}
```

### 명령 테이블 (funcs_37012)

| 명령 | 함수 | 설명 |
|------|------|------|
| 0x00 | sub_36E3D | 팔레트 채우기 (단색) |
| 0x01 | sub_36E57 | 팔레트 복사 (768바이트) |
| 0x02 | sub_36E65 | 팔레트 RLE 디코딩 |
| 0x03 | sub_36EA7 | 다중 구간 복사 |
| 0x04+ | ... | RLE 픽셀 디코딩 |

### RLE 픽셀 디코딩

명령 >= 0x04인 경우:
- 포맷: `[count][color1][color2]`
- count: 반복 횟수
- color1: 팔레트 인덱스
- color2: 검증 값 (color1과 동일해야 함)

출력은 320x200 = 64000 픽셀의 팔레트 인덱스 배열입니다.

## 주요 발견

1. **처음 두 프레임은 제어 프레임**: 팔레트 초기화에 사용됨
2. **프레임 데이터 크기 편차 큼**: 2바이트에서 65279바이트
3. **키 프레임은 약 64KB**: 320x200 원시 크기에 근접
4. **차분 프레임은 작음**: 변화된 부분만 포함
